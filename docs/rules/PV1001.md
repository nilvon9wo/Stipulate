# PV1001: Implementation strengthens its contract's precondition

**Severity:** Error

An implementation or override must accept every argument its contract accepts (the Liskov
substitution principle): its validation attributes may be weaker than the contract's, but not
stronger. A caller that only knows the interface can't know about the extra demand.

```csharp
public interface IMultiplier
{
    int[] Multiply([MinLength(1)] int[] array);
}

public class Multiplier : IMultiplier
{
    // error PV1001: Parameter 'array' of 'Multiplier.Multiply(int[])' strengthens the
    // precondition of 'IMultiplier.Multiply(int[])': [MinLength(2)] requires Length >= 2,
    // but the contract accepts Length >= 1
    public int[] Multiply([MinLength(2)] int[] array) => array;
}
```

The same goes for a property's setter, and for a constraint the contract doesn't have at all:

```csharp
public interface INamed
{
    string Name { set; }
}

public class Person : INamed
{
    // error PV1001: the contract accepts any name, but [MaxLength(50)] rejects longer ones
    [MaxLength(50)]
    public string Name { set { } }
}
```

## How to fix it

Accept what the contract accepts: restate its attribute, or weaken it.

```csharp
public interface IMultiplier
{
    int[] Multiply([MinLength(1)] int[] array);
}

public class Multiplier : IMultiplier
{
    public int[] Multiply([MinLength(1)] int[] array) => array;
}
```

If the implementation really can't accept everything, the contract is wrong: strengthen the
contract's attribute instead, so every caller sees the requirement.
