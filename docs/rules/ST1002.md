# ST1002: Implementation doesn't restate its contract's validation attribute

**Severity:** Warning

Dropping a contract's validation attribute is a legal weakening: the implementation accepts more.
But it should be explicit, so that the implementation's signature shows what it accepts, and so
that dropping it by accident doesn't go unnoticed.

```csharp
public interface IScale
{
    void Set([Range(1, 10)] int level);
}

public class Scale : IScale
{
    // warning ST1002: Parameter 'level' of 'Scale.Set(int)' doesn't restate [Range(1, 10)] from
    // 'IScale.Set(int)'. Restate it, or state a weaker constraint for each of its bounds to
    // accept more on purpose.
    public void Set(int level) { }
}
```

## How to fix it

Restate the attribute; the code fix "Restate [Range(1, 10)] from the contract" does it for you,
one at a time or for the whole document:

```csharp
public interface IScale
{
    void Set([Range(1, 10)] int level);
}

public class Scale : IScale
{
    public void Set([Range(1, 10)] int level) { }
}
```

Or accept more on purpose, by stating a weaker constraint for each of its bounds:

```csharp
public interface IScale
{
    void Set([Range(1, 10)] int level);
}

public class Scale : IScale
{
    public void Set([Range(int.MinValue, int.MaxValue)] int level) { }
}
```

For a bound on the length, `[MinLength(0)]` states no lower bound and `[MaxLength]` no upper one.
For `[Required]`, make the parameter or property nullable:

```csharp
public interface IGreeter
{
    void Greet([Required, MinLength(2)] string name);
}

public class Greeter : IGreeter
{
    public void Greet([MinLength(0)] string? name) { }
}
```
