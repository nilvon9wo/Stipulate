# ST1003: Implementation weakens its contract's guarantee

**Severity:** Error

What an implementation hands back (a property's value, an `out` or `ref` parameter) must satisfy
everything its contract promises: its validation attributes may be stronger than the contract's,
but not weaker or missing. A caller that only knows the interface relies on the promise.

```csharp
public interface IInventory
{
    [Range(0, 1000)]
    int Count { get; }
}

public class Inventory : IInventory
{
    // error ST1003: ... [Range(0, 1000)] requires Value <= 1000, but the implementation accepts Value <= 2000
    [Range(0, 2000)]
    public int Count => 3;
}
```

A missing attribute weakens a guarantee too, and so does a nullable type where the contract
requires a value:

```csharp
public interface IParser
{
    bool TryParse(string text, [MinLength(1)] out string result);
}

public class Parser : IParser
{
    // error ST1003: ... weakens the guarantee of 'IParser.TryParse(string, out string)': it doesn't
    // restate [MinLength(1)]
    public bool TryParse(string text, out string result)
    {
        result = text;
        return true;
    }
}
```

A property with both a getter and a setter, and a `ref` parameter, both take and hand back
values: their attributes are preconditions and guarantees at once, so they must match the
contract's exactly.

## How to fix it

Promise what the contract promises, or more:

```csharp
public interface IInventory
{
    [Range(0, 1000)]
    int Count { get; }
}

public class Inventory : IInventory
{
    [Range(0, 100)]
    public int Count => 3;
}
```
